# amonhen-gpgui 画面の方針（案）

[English](../ui.md)

鍵を一覧で並べて管理するのではなく、**自分が使える鍵・使えた鍵**を主に管理する。他者の鍵と、鍵サーバーなどから一時的に取ってきた鍵は、別の場所で扱う。

## 4 つの場所

| 場所 | 中身 | 役割 |
|---|---|---|
| **自分の鍵**（主画面） | 自分が使える鍵、使えた鍵 | 自分の鍵の使える状態を保つ（期限、バックアップ、カード、SSH） |
| **他者の鍵** | 暗号化の宛先や、署名の検証に使う鍵 | 必要なものを保管する |
| **SSH の署名者** | SSH で署名した git のコミットを検証する相手、受け入れた鍵、一覧 | git の allowed signers のファイルを保つ（[allowed-signers.md](allowed-signers.md)） |
| **受け入れ前の鍵** | 鍵サーバー・WKD・GitHub・GitLab で取ってきた鍵、ファイルで受け取った鍵、SSH の署名者のために取ってきた SSH の署名用の鍵 | 中身を確かめてから「他者の鍵」に取り込む（SSH の署名者に受け入れる）か、捨てる |

gpg が 2.4.6 より古ければ、どの場所でも上に警告を出し、GnuPG の更新か、設定で新しい gpg を選ぶことを勧める。鍵の一覧は出すが、一部の操作（SSH の入れ・切りなど）は失敗することがある。

## 主画面: 自分の鍵

鍵を「使えるかどうか」で 3 段に分ける。

```
自分の鍵                                         [+ 作成] [取り込み]
─────────────────────────────────────────────────────────────────
使える
  🔑 Alice <alice@example.com>                    ⚠ 30日で期限切れ [延長]
     署名 ✓ この PC   復号 ✓ この PC   SSH ✓ この PC
  💳 Work <a@corp.example>
     署名 ✓ YubiKey   復号 ✓ YubiKey   SSH ✓ YubiKey  (カード未接続なら「カードを挿す」)

この PC では使えない
  🖥 Alice (自宅 PC 用) <alice@home.example>
     秘密鍵はこの PC にない ・ 公開鍵だけ    [秘密鍵を取り込む…]

使えた鍵（履歴）                                       ▸ 3 本
  ⌛ Alice 2019 — 2024-03 期限切れ   [延長] [失効させる…]
  ⛔ Old <old@example.com> — 2021 失効
```

- **鍵ごとに、何ができるかを用途別に見せる。** 署名・復号・SSH（認証）について「できるか」と「どこでできるか（この PC、YubiKey）」を並べる。主鍵とサブ鍵の違いは詳細画面まで出さない。
- **「自分の鍵」の判定:** 所有者信頼が絶対的（`u`）な鍵か、秘密鍵（スタブやカード上の鍵を含む）がある鍵。秘密鍵の有無だけで決めると、「秘密鍵は別の PC にある自分の鍵」が漏れるため。
- **段の分け方:**
  - 使える: 有効で、用途のどれかの秘密鍵がこの PC かカードにある。
  - この PC では使えない: 有効だが、秘密鍵がこの PC にない（公開鍵だけ、またはスタブだけ）。
  - 使えた鍵（履歴）: 期限切れ・失効。既定では畳む。期限切れは延長で復活でき、失効させれば履歴として確定する。昔の鍵で暗号化されたものを復号するため、秘密鍵は残す前提。
- **段の中の並び:** 使える段とこの PC では使えない段は、期限が近い順に並べ、期限のない鍵は最後に置く。延ばす必要のある鍵が上に来る。使えた鍵は新しい順。自分の鍵は数本なので、並べ替えのメニューは置かない。
- **警告は自分の鍵にだけ出す:** 期限が近い、バックアップを取っていない、失効証明書（`openpgp-revocs.d`）がない。
- **危険な操作**（秘密鍵ごと削除）は詳細画面の奥に分けて置き、先にバックアップを促す（[architecture.md](architecture.md) の「自分の鍵を失わない」）。

## 他者の鍵

- 暗号化の宛先・署名の検証のために保管する鍵。
- 有効性は記号ではなく言葉で示す（完全・部分的・不明・無効・期限切れ・失効。自分の鍵は究極）。
- 「鍵に署名…」で、自分の鍵でその鍵に署名する（`Gpg::sign_key`。信頼の輪（Web of Trust））。署名すると、自分の鍵束の中でその鍵が有効になる。先にフィンガープリントを持ち主と照らし合わせるよう促す。既定は書き出さない署名（ローカル署名）とし、鍵サーバーに載る署名は選んだときだけにする。証明には主鍵の秘密鍵が要る（サブ鍵ではできない）ので、この Mac にもカードにもなければ、メニューにそう添えて押せなくする。
- 「ローカル署名」（ツールバーのメニュー）で、主鍵のある Mac でしたローカル署名を、主鍵のない Mac へ運ぶ（ふつうの書き出しでは落ちる）。「ローカル署名を書き出す…」で、自分の鍵がローカル署名した鍵を、その署名ごと保存する（`Gpg::export_local_signatures`。`--export-options export-local`）。「ローカル署名を取り込む…」で、もう一方の Mac の鍵束にすでにある鍵にだけ署名を加える（`Gpg::import_local_signatures`。`--import-options import-local,merge-only`）。確かめていない鍵が一緒に入ることはない。飛ばした鍵と、先に受け入れる方法を知らせる。署名は主鍵がしたものなので、途中で書き換えられれば gpg がはねる。
- 同じメニューで、その署名を頼む。主鍵のない Mac の「別の Mac に署名を頼む…」は、まだ署名していない鍵を並べる。フィンガープリントを照らし合わせた鍵を選ぶと、その公開鍵を自分の鍵（署名用のサブ鍵）で署名して保存する（`Gpg::create_signing_request`）。主鍵のある Mac の「署名の依頼を開く…」は、自分の鍵が署名し、その主鍵がこの Mac にある依頼だけを開く（`Gpg::open_signing_request`）。他人の鍵を紛れ込ませることはできない。鍵を名前とフィンガープリントで並べ、「署名して保存…」で取り込み（`Gpg::import_signing_request`）、選んだ鍵に依頼にある UID でローカル署名し、その鍵のローカル署名だけを、もう一方の Mac の「ローカル署名を取り込む…」のために保存する。最初の Mac に署名できる鍵がなければ依頼は作れないので、もう一方の Mac で受け入れ前の鍵から鍵を取り込む。
- 所有者信頼（その持ち主が、ほかの鍵をどれだけ確かめてから署名すると見なすか）は、行のメニュー（所有者信頼）か、鍵の詳細の概要で選ぶ。決めていない・信頼しない・ある程度・完全に、の 4 つ（`Gpg::set_owner_trust`）。絶対的は出さない。自分の鍵のもので、付けるとその鍵が自分の鍵になるため。何に効くかを短く添える（gpg の既定では、完全に信頼する人の鍵 1 つ、またはある程度信頼する人の鍵 3 つの署名で、その鍵が確認済みになる）。
- 行のメニューの「自分の鍵にする…」は、秘密鍵が別のコンピュータにある自分の鍵のためのもの。そのコンピュータでフィンガープリントを照らし合わせるよう促して確かめたあと、所有者信頼を絶対的にし、鍵は自分の鍵（この Mac では使えない）に移る。こうした所有者信頼だけで自分の鍵になっている鍵には、メニューに「自分の鍵ではない…」があり、所有者信頼を「決めていない」に戻して他者の鍵に移す。秘密鍵のある鍵は常に自分の鍵なので、これはない。
- 削除は公開鍵の削除だけ（秘密鍵のある鍵は gpg が拒む）。

## 受け入れ前の鍵

前の名前は「一時保管」。gpg 自体には「一時的な鍵」という概念がないので、**別の鍵束（アプリが管理する一時用の `--homedir`）を使う。** 以下とコードでは、これを staging の鍵束と呼ぶ。

1. 鍵サーバー・WKD・GitHub・GitLab で探すと、結果は staging の鍵束に入る。ファイルで受け取った鍵は `gpg --show-keys` で取り込まずに中身を見られる。
2. 指紋・UID・署名を確認してから「取り込む」を押す。staging の鍵束から書き出し、本来の鍵束に取り込む（入手元の鍵サーバー・WKD・web アドレス・ファイルは引き継ぐ）。
3. 使わなかった鍵は捨てるだけで、本来の鍵束は散らからない。

git やメールの署名検証は本来の鍵束しか見ないので、そうした用途に使う鍵は取り込む必要がある。

SSH の署名者のために取ってきた SSH の署名用の鍵も、受け入れるまで、別の段としてここに置く（アカウントから取ったまま、または持ち主とフィンガープリントを照らし合わせてから受け入れる。照らし合わせる画面は等幅の字体で出す）。staging の鍵束と同じく、メモリの中にだけ持つ。

## 信頼の輪

主画面には出さず、鍵の詳細で控えめに出す。

- 確認済み・一部確認済みの他者の鍵の詳細で、「確認の根拠」に、どの署名で確認済みになったかを並べる。自分の鍵と、所有者信頼を完全・ある程度にした確認済みの鍵による署名（`Keyring.introducers`。gpg の pgp 信用モデルと同じく、正しく、取り消されていない署名だけ）。
- 自分の鍵については、署名した鍵の数だけを詳細に出す（`Keyring.signerCount`）。誰の署名かは署名タブで見る。
- グラフでは描かない。

## core に足りないもの

済み:

- 所有者信頼と秘密鍵の場所から「自分の鍵」と段（使える／この PC では使えない／履歴）を判定する処理（`Key::is_mine`・`Key::status`）。用途（証明・署名・復号・認証）ごとに、この PC・カード・ほかの場所のどこで使えるかも返す。
- `--show-keys`（取り込まずに中身を見る）への対応（`Gpg::show_keys`）。
- 失効証明書の有無の確認（`Gpg::has_revocation_certificate`）と、ないときの作り直し（`Gpg::save_revocation_certificate`）。
- staging の鍵束（`Gpg::staging`・`discard_staging`）と、本来の鍵束へ公開鍵だけを移す処理（`copy_public_keys_to`）。`discard_staging` はstaging の鍵束の印（`.amonhen-staging`）があるディレクトリしか消さない。
- 鍵サーバー（`receive_keys`。フィンガープリントで取る）・WKD（`locate_external_key`。メールアドレスで探し、なければ鍵サーバー）からの取得。新しい鍵束の dirmngr には鍵サーバーの設定がないので、受け入れ前の鍵では FE が鍵サーバーを決めて渡す。GitHub・GitLab（`fetch_from_code_host`。`https://github.com/<名前>.gpg` を `--fetch-keys` で取る）: core が、確かめた利用者名から URL を組み立て、その URL を `--key-origin` で入手元として記録する（`--fetch-keys` だけでは記録されない）。
- カードの状態（`Gpg::card_status`、`Card::holds` で鍵一覧の `SecretState::OnCard` と照らし合わせる）。カードがないときの動きは確認済みだが、実際のカードでの出力の解析はまだ確かめていない。
- 自分の鍵の編集（有効期限・UID・サブ鍵・パスフレーズ・所有者信頼・失効）。
- 他者の鍵への署名（`Gpg::sign_key`）。
- 鍵の UID に付いた、ほかの鍵による署名の一覧（`Gpg::certifications`。`--check-signatures` で確かめ、自己署名は除く）。
- 鍵サーバーへの送信（`Gpg::send_keys`。失効させた自分の鍵を知らせるのに使う）。
- gpg-agent の SSH 鍵（`Gpg::ssh_support`・`enable_ssh_support`・`ssh_keys`・`set_ssh_key_enabled`・`export_ssh_key`・`ssh_public_key`・`delete_ssh_key`）と、既存の SSH 秘密鍵の取り込み（`Gpg::add_ssh_key`）、取り込んだ鍵のバックアップと戻し（`export_ssh_key_backup`・`import_ssh_key_backup`）。主画面の「SSH ✓ この PC」は、認証サブ鍵の keygrip を `SshKey` と照らし合わせて出す。

意図して作らない:

- 鍵サーバーで名前から探す（`--search-keys`）。既定の keys.openpgp.org は、メールアドレスかフィンガープリントで完全に一致する鍵しか返さない。名前で探せる鍵サーバー（keyserver.ubuntu.com など）は、誰かが他人の名前で上げた鍵を多く返し、名前は鍵について何も示さない。受け入れ前の鍵では、代わりにメールアドレス（まず WKD）、フィンガープリント、GitHub・GitLab の利用者で探す。

## macOS アプリ（SwiftUI）でできること

- 自分の鍵の一覧（3 段）と他者の鍵の一覧。
- 他者の鍵は表で出す。列は名前（ほかの UID の数を添え、マウスを載せると中身）、メールアドレス、有効性、所有者信頼、鍵 ID、作成日、期限、方式。どの列でも並べ替えられ、有効性は完全が先で失効が最後、所有者信頼は完全から決めていないの順、期限は期限のない鍵が最後に来る。ダブルクリックで詳細、スペースでクイックルック（フィンガープリント・有効性・期限・方式。選ぶ行を変えるとついていき、もう一度スペースで閉じる）、右クリックで行の操作（「取り直す」で、入手元か鍵サーバーから鍵を取り直し、延ばした期限や失効を受け取る。取ってきた鍵は受け入れ前の鍵に「鍵束にあり」の印と手元の鍵の期限を添えて置き、「更新」で鍵束の鍵に合わせる。受け入れ前の鍵の検索欄には、最初に引いたもの（WKD ならメールアドレス、GitHub・GitLab ならアカウント、ほかはフィンガープリント）を出す）。期限切れ・失効の鍵は薄く出す。見出しを右クリックして列を出し入れでき（名前は消せない）、見出しをドラッグして列を並べ替えられる。出す列とその並び・幅、行の並べ替えは覚えておく。ツールバーの絞り込みのメニューで、すべて・完全に有効・完全には有効でない（部分的も含む）・期限切れ・失効のどれを出すかを選べ、選んだものは覚えておく。合う鍵がなければそう出し、すべて表示のボタンを置く。
- サイドバーに、自分の鍵と他者の鍵の数を出す。
- 両方の一覧を、ツールバーの検索欄で絞り込む。語はすべて、名前かメールアドレス（どの UID でも、大文字小文字を区別しない）に合うか、4 文字以上の 16 進の語なら主鍵かサブ鍵のフィンガープリントに合う必要がある。区切りの空白ごと貼り付けたフィンガープリントは、まとめて比べる。探している間、自分の鍵の画面は SSH の段を隠し、使えた鍵の段を開く。受け入れ前の鍵には鍵サーバーを探す欄が別にあるので、ここでは絞り込まない。
- 期限の延長（期限が近い鍵と、期限切れの鍵の「延長…」、行のメニュー）。主鍵と、期限のある失効していないサブ鍵をまとめて同じ期限にする（主鍵だけ延ばしても、サブ鍵が切れれば署名や復号に使えないため）。延ばせるのは主鍵の秘密鍵がこの PC かカードにある、失効していない鍵だけ。
- 名前とメールアドレス（行のメニューの「名前とメールアドレス…」）。UID を足す・主にする・失効させる。消すことはしない（渡したあとでは相手の手元から消えないので、失効させて使わないと知らせる）。最後の 1 つは失効させられない。gpg は印のない鍵に UID を足すとそれを主にしてしまうので、足したあとで主を付け直し、選んだときだけ足したものを主にする。変えたら、更新した公開鍵を鍵サーバーに送るか書き出すよう勧める。主鍵の秘密鍵がこの PC かカードにある、失効していない鍵だけ。
- パスフレーズの変更（行のメニューの「パスフレーズを変える…」）。今のものと新しいものは pinentry が聞き、アプリは触れない。これまでのバックアップは古いパスフレーズで守られたままなので、確かめるときにそう伝え、変えたらバックアップを取り直すよう勧める。秘密鍵がこの PC にある鍵だけ（カード上の鍵は PIN で守られる）。gpg は今のパスフレーズの入力を取り消しても 0 で終わるので、`ERROR` の状態行で失敗と見分ける。
- 秘密鍵のバックアップ（行のメニュー）。保存先を選ばせ、ASCII 形式で書き出す。パスフレーズで守られたままで、ファイルは持ち主だけが読める（0600）。カード上の鍵は書き出せないので、秘密鍵がこの PC にある鍵だけ。
- 鍵の作成（ツールバーの「＋」、鍵がないときの画面）。名前・メール・期限（既定 2 年）だけを聞き、方式と用途は gpg の既定に任せる。作ったらすぐバックアップを勧める。
- 鍵の取り込み（ツールバー、鍵がないときの画面）。公開鍵・秘密鍵のバックアップ・失効証明書のファイルを選ばせ、1 つずつ取り込んで結果をまとめて知らせる。読めないファイルがあっても残りは取り込む。受け入れ前の鍵を通さず、本来の鍵束に直に入れる（自分で選んだファイルなので）。
- バックアップの記録がない自分の鍵（秘密鍵がこの PC にあるもの。昔のものの復号に要るので、使えた鍵も含む）には「バックアップがありません」と警告し、「バックアップ…」へ導く。gpg は記録しないので、アプリで書き出した日時を鍵のフィンガープリントごとに覚える（UserDefaults）。ほかの方法で取ったバックアップは、行のメニューの「バックアップ済みにする…」で確かめてから記録する。
- 失効証明書がない自分の鍵には「失効証明書がありません」と警告し、「作成…」で作り直す（主鍵の秘密鍵がこの PC かカードにある、失効していない鍵だけ）。gpg が鍵を作るときと同じ `openpgp-revocs.d` に置き、この Mac 以外にも写しを置くよう促す。
- 自分の鍵の行で橙に目立たせるのは急ぐものだけ（14 日以内の期限切れ）。60 日以内の期限切れ・「バックアップがありません」・「失効証明書がありません」・SSH の段の「SSH サポートが無効」は、ボタンと一緒に灰色で出す。
- 鍵の失効（行のメニューの「鍵を失効させる…」）。理由（もう使わない・置き換えた・漏れた・示さない）と 1 行の説明を選ばせ、元に戻せないことをもう一度確かめてから失効させる。バックアップの記録がなければ、その場でバックアップを促す（失効させても、昔のものの復号に秘密鍵が要るため）。失効させられるのは、主鍵の秘密鍵がこの PC かカードにある鍵だけ。
- 公開鍵を渡す（行のメニュー）。ファイルに書き出すか、鍵サーバー（keys.openpgp.org。送り先はアプリが決めて渡す）に送る。送ったものは取り消せないので、誰でも取得できるようになることを確かめてから送る。失効させたあとは、ほかの人が知るにはこれが要るので、すぐに勧める。
- SSH の公開鍵を渡す（行のメニューの「SSH の公開鍵をコピー」「SSH の公開鍵を書き出す…」）。失効・期限切れでない認証サブ鍵のうち新しいものを、`authorized_keys` に書く 1 行の形で出す（ファイルは 0644）。gpg-agent がまだこの鍵を SSH に出していなければ、そう添える。
- 自分の鍵を SSH に出す・止める（行のメニューの「SSH に使う」「SSH に使うのをやめる」）。出すときは、gpg-agent が秘密鍵を持つ、使える認証サブ鍵のうち新しいものを出す。止めるときは、鍵のうち gpg-agent が出しているものをすべて止める。SSH サポートが切れていれば、入れるまで使えないと添える。
- SSH 用のサブ鍵を加える（行のメニューの「SSH 用のサブ鍵を加える…」。使える段にあり、使える認証サブ鍵がなく、主鍵の秘密鍵がこの PC かカードにある鍵）。確かめてから、gpg の既定の方式で、鍵と同じ期限の認証サブ鍵を加え、SSH に出す。そのあと、SSH の公開鍵のコピーと、バックアップの取り直しを勧める（前のバックアップにはサブ鍵がないため）。
- 受け入れ前の鍵。検索欄の横のポップアップメニューで、探す種類を選ぶ。メールアドレス（WKD、なければ keys.openpgp.org）かフィンガープリント（keys.openpgp.org）で探すか、GitHub・GitLab の利用者が公開している鍵を取ってくる（ユーザー名で。`github:名前`・`gitlab:名前` かプロフィールの URL でもよく、これらやメールアドレス・フィンガープリントを貼ると種類も合わせる。その鍵がアカウントに登録されていることしか示さないので、持ち主とのフィンガープリントの照合は要る。アカウントの SSH の署名用の鍵も一緒に取り、推し量った候補から選んだメールアドレスで SSH の署名者に受け入れる。[allowed-signers.md](allowed-signers.md) を参照）か、ファイルから入れる（秘密鍵を含むファイルでも公開鍵だけを入れる）。UID・フィンガープリント・入手元（鍵サーバーのホスト名・メールのドメインの WKD・github.com などの web アドレス・ファイル）・作成日・期限を見て「取り込む」（本来の鍵束に公開鍵だけを移す）か「捨てる」。短い鍵 ID や名前では探さない。staging の鍵束は起動ごとに一時ディレクトリに作り、アプリの終了時に捨てる。名前に作ったプロセスの ID を入れ、アプリが落ちて残ったものは、次の起動時に捨てる（そのプロセスが動いているもの、staging の鍵束の印がないものには触らない）。
- 他者の鍵に署名する（行のメニューと鍵の窓の「鍵に署名…」。表の行ごとにはボタンを置かない。有効でない鍵が、どれも解消すべきものに見えないように）。フィンガープリントを大きく出し、持ち主と照らし合わせたと答えるまで署名できない。確かめた UID だけを選んで署名する（あとで UID が増えても、確かめていないものには署名しない）。署名に使う自分の鍵を選ぶ。既定は書き出さない署名で、鍵と一緒に公開する署名は選んだときだけ。
- 他者の鍵に付けた自分の署名を取り消す（有効な鍵の行のメニューの「自分の署名を取り消す…」）。その鍵への自分の署名を示し、ローカル署名は消す（公開していないので、秘密鍵も要らない）。公開した署名は失効させる（`Gpg::withdraw_certifications`。主鍵の秘密鍵が要る。ほかの人に知らせるには鍵を送り直す）。ほかの人の署名で有効でない限り、鍵は有効でなくなる。終わったら、自分の署名だけが変わったことを確かめる。
- 鍵の詳細（行のメニューの「詳細…」、行のダブルクリック、メニューの「鍵」>「詳細を表示」⌘I）。鍵ごとに窓を開き（もう一度開くと同じ窓を前に出す）、鍵どうしを並べて見比べられる。鍵が鍵束からなくなれば、窓にそう出す。上に名前とフィンガープリント（他者の鍵には「取り直す」も）、残りはタブに分ける。概要: 鍵 ID（gpg の長い形。横のボタンで、長い形・0x 付きの長い形・短い形・0x 付きの短い形と、区切りあり・なしのフィンガープリントを並べ、押すとコピーする。「鍵」のタブでもサブ鍵ごとに同じ）・有効性・所有者信頼（他者の鍵。メニューで変えられる）・確認の根拠（他者の鍵）・作成日・期限・失効の理由と説明（秘密鍵が漏れたという理由は目立たせる）・方式・入手元（鍵サーバー・メールアドレスのドメインの WKD・ファイルなど。ホスト名と、最後に取り直した日を添える。自分の鍵は分かるときだけ）、自分の鍵なら秘密鍵の場所（この PC・スマートカード・別の場所）・バックアップの記録・失効証明書・署名した鍵の数・SSH 用に設定済みかとその SSH のフィンガープリント。名前とメール: UID ごとの有効性と、失効した UID の理由。鍵: 主鍵とサブ鍵ごとの用途・作成日・期限・失効の理由・秘密鍵の場所・フィンガープリント・keygrip、gpg-agent が秘密鍵を持つ認証サブ鍵なら SSH のフィンガープリント（`SHA256:…`）。署名: 鍵の UID に付いたすべての署名を、署名した人（鍵束にあれば名前、なければ鍵 ID だけ）・UID・確かめた結果（正しい・正しくない・署名した鍵がなく確かめられない・取り消し済み）・日付・鍵と一緒に公開する署名かと一緒に出す。自分の鍵と、自分が確認済みにした鍵による署名を先に出す。ほかの人の署名は、知らない人のものは本物の保証にならないので、その下に薄く、そう添えて出す。
- 他者の公開鍵の削除（行のメニュー）。確かめてから消す。確認済みにした署名も一緒に消えることを伝える。
- 自分の鍵の画面の SSH の段。gpg-agent の SSH サポートが無効ならそう知らせ、確かめてから有効にする（gpg-agent.conf に足し、gpg-agent を起動し直す）。OpenPGP の鍵でない SSH の鍵（ssh-add で取り込んだ鍵）を説明（comment）で並べ、SSH に使うかを切り替える。それぞれのメニューで、公開鍵を `authorized_keys` に書く 1 行としてコピー・書き出しし、バックアップし（「バックアップ…」。gpg-agent が保存している形のまま、取り込んだときのパスフレーズで守られたものを、本人だけが読める `<keygrip>.key` というファイルに。パスフレーズは聞かない。gpg-agent がパスフレーズなしで持っている鍵はバックアップせず、守り方を知らせる）、確かめてから gpg-agent から消す（取り込んだ元の鍵ファイルには触れない）。既存の SSH 秘密鍵のファイル（`~/.ssh`）の取り込みと、バックアップからの戻しを、同じ「SSH の鍵を取り込む…」で行う（gpg 2.5.14 から。古い gpg では、ファイルを `private-keys-v1.d` に写して戻す方法を知らせる）。`SSH_AUTH_SOCK` に指すソケットの場所を示す。
- SSH の署名者（[allowed-signers.md](allowed-signers.md)）。一覧はサイドバーの「SSH の署名者」の下に並べる（メールのメールボックスと同じ）。「SSH の署名者」ではすべての人、一覧を選ぶと、人の上にその一覧の allowed signers のファイル・「git に設定…」・「一覧を除く…」を出す。人は開け閉めできる表にする。人の行（メール・アカウント・一覧と、短い状態: 新しい鍵・消えた鍵・取れない・一覧なし）を開くと、その人の鍵の行（フィンガープリント・入手元のアカウント・確かめ方・退役・消えた・アカウントにも）が並ぶ。操作は行の右クリックのメニュー。人なら「変化を確かめる」「受け入れ前の鍵を見る」「一覧に入れる」「この一覧から外す」「人を除く…」、鍵なら「アカウントにもあると記録」「鍵を退役させる…」「鍵を除く…」。一覧（それぞれ allowed signers のファイル 1 つ。「git に設定…」のシートで gpg.ssh.allowedSignersFile の働きを説明し、すべてのリポジトリ用と 1 つのリポジトリ用の `git config` のコマンドを見せ、押すとコピーする）、GitHub・GitLab のアカウントと受け入れた鍵を持つ人（鍵ごとの確かめ方、退役させた鍵とその時刻）、「変化を確かめる」（取ってきた鍵は受け入れ前の鍵へ。アカウントから消えた鍵には「退役させる」）、鍵ごとの「鍵を退役させる…」「鍵を除く…」、「allowed signers のファイルを取り込む…」（行は受け入れ前の鍵に置き、入れる一覧・「すべて受け入れる」・取り込めない行とその理由を出す。取り込んだ鍵は「変化を確かめる」でその人のアカウントと比べる）。記録は署名できる自分の鍵で署名する（複数あればツールバーで選ぶ）。自分の鍵の署名がない記録や、アプリの外で変えられたファイルは知らせ、「ファイルを書き直す」で記録から書き直す。git の設定は変えない。
- 設定（⌘,）。使っている gpg のプログラムと版を示す。「選択…」で別の gpg を選ぶ（/opt などの隠れたフォルダーも見せ、symlink は解かずに残すので、Homebrew で更新しても使える）。版を読めたときだけ使う。「自動で探す」で、`PATH`・/opt/homebrew/bin・/usr/local/bin・/usr/local/MacGPG2/bin の順で最初の gpg に戻す。選んだものは覚え（UserDefaults）、替えると鍵束を読み直し、受け入れ前の鍵は空からやり直す（staging の鍵束は前の gpg で作ったため）。起動の引数 `--gpg` が先で、そのとき設定は示すだけ。設定では、鍵サーバー（keys.openpgp.org・keyserver.ubuntu.com、または hkps://・hkp://・https://・ldaps:// で始まるほかの URL）も選ぶ。受け入れ前の鍵をフィンガープリントで探すのにも、自分の公開鍵を送るのにも使う。受け入れ前の鍵が名前を引く仕組みも選ぶ。GnuPG 内蔵（既定。/etc/resolv.conf しか読まない）か macOS（dirmngr の `standard-resolver`。VPN やドメインごとの DNS でも引ける）。どちらもすぐに staging の `dirmngr.conf` に書き、中の鍵はそのまま。自分の鍵束の dirmngr の設定は変えない。起動の引数 `--keyserver` が先。
- 秘密鍵ごとの削除（行のメニューのいちばん下）。秘密鍵がこの PC にあるなら、バックアップの記録があるまで消させない（その場でバックアップできる）。失効させていなければ、ほかの人がこの鍵に暗号化し続けることを伝え、失効へ導く。フィンガープリントの最後の 4 文字を打ってもらい、最後にもう一度確かめる。gpg-agent は秘密鍵を消すときに pinentry で確かめないので、アプリの確認がすべて。
- パスフレーズは gpg-agent の pinentry が聞く。入力を取り消したときは何も知らせずに元の画面に戻り、パスフレーズが違ったときはそう知らせる。pinentry を出せない（端末用の pinentry-curses などを使っている）ときは、gpg-agent.conf に足す `pinentry-program` の行（入っている pinentry-mac の場所）を示す。設定はアプリでは書き換えない。
